A document id is the sha256 of its text, so a summary always points at text that cannot change under it. The contract and the browser compute the same bytes, and both are held to the vectors below.

## The bytes

The digest runs over the UTF-8 bytes of `fineprint-doc-v1` and a newline, then, for the title and each clause in order, the byte length of the text in UTF-8, a colon, the text, and a newline. The length prefix matters: with only a newline between texts, a line break inside a clause could move a boundary and make two different documents one (found by `scripts/mutate.py`).

The texts are normalised first, because that is what the contract stores: line endings become `\n` and the whitespace Python's `str.strip()` removes is taken off both ends of the title and of each clause.

```python title="contracts/fineprint.py"
def doc_hash(title: str, clauses: list) -> str:
    """
    The id of a document: sha256 over the UTF-8 bytes of

        "fineprint-doc-v1\\n"
        then, for the title and each clause in order,
        <byte length of the text in UTF-8> ":" <text> "\\n"

    The title and clauses are the normalised texts: line endings as \\n and
    surrounding whitespace stripped. The site computes the same bytes in the
    browser, held to tests/vectors.json.
    """
    digest = hashlib.sha256()
    digest.update((HASH_VERSION + "\n").encode("utf-8"))
    for text in [title] + list(clauses):
        raw = text.encode("utf-8")
        digest.update((str(len(raw)) + ":").encode("utf-8") + raw + b"\n")
    return digest.hexdigest()
```

The same in JavaScript, which is the code the site runs:

```js title="web/examples/hash-a-document.mjs"

import { docIdOf } from '../lib/hash.mjs';

const id = docIdOf('Kiln airdrop terms', [
  'Hold 100 KILN at the Oct 1 snapshot.',
  'Wallets created later are not eligible.',
  'Claims close on Dec 15.',
]);
console.log(id);
```
